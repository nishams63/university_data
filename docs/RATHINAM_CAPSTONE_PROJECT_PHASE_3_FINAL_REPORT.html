2. Database Schema Hardening & Concurrency Safety

To ensure zero data corruption during simultaneous multi-threaded data ingestion across RTC departmental streams, the database layer has been fortified with database-level integrity constraints and transactional boundaries:

Relational Constraint / Pragma Technical Definition Safety & Concurrency Invariant Guaranteed
uq_raw_event_id UniqueConstraint('event_id') on RawEvent Guarantees storage-level idempotency. Duplicate delivery races are aborted at the B-Tree index layer.
uq_report_date_domain UniqueConstraint('report_date', 'domain') on DailyReport Prevents duplicate daily report partitions. Ensures exactly one logical aggregate entity per day per domain.
uq_report_version_id_num UniqueConstraint('report_id', 'version_number') Enforces strict monotonic versioning (v1 → v2 → v3). Prevents version collision under concurrent recalculation.
PRAGMA journal_mode = WAL Write-Ahead Logging enabled on SQLite engine Allows concurrent non-blocking readers while writer appends to WAL file. Eliminates reader starvation.
PRAGMA busy_timeout = 10000 10-second spinlock timeout on locked database Prevents OperationalError: database is locked exceptions during bursty ingestion spikes.
PRAGMA foreign_keys = ON Enforced on every engine connection hook Guarantees referential integrity from versions and audit logs back to parent reports and events.
Atomic Transaction Boundary session.begin() wrapping mutation pipeline If any step fails (e.g. version insert or audit write), the entire transaction rolls back cleanly.
